## 1. System Architecture & Tech Stack Summary

- **Backend Framework:** 
  - **Framework:** FastAPI version `0.115.12` running on Python `3.11.x` with Uvicorn `0.34.3`.
  - **Data Validation & Settings:** Pydantic `v2.11.5` (`api/schemas.py`) and `pydantic-settings` `v2.9.1`.
  - **Primary Inference LLM:** Groq LPU API (`GroqChatClient` using `llama-3.3-70b-versatile` with fallback to `mixtral-8x7b-32768`).
  - **Sparse Keyword Scoring:** `rank_bm25` (`v0.2.2`, `BM25Okapi`).
  - **RAG Evaluation Framework:** DeepEval `v2.6.5` with custom `GroqDeepEvalWrapper` adapter.
  - **Storage:** SQLite3 database (`leasesight.db`) for contact inquiries, migration results, and live evaluation logs.
  - **PDF Export Engine:** ReportLab `v4.2.5` generating clean multi-page legal summaries.
  - **Legacy UI:** Streamlit `v1.45.1` (`app.py`) maintained for desktop prototyping.

- **Frontend Framework:**
  - **Framework:** Next.js App Router (`v16.2.4`), React (`v19.2.4`), TypeScript (`v5.x`).
  - **Styling:** Vanilla CSS design system (`globals.css`) alongside Tailwind CSS (`v4.x`) and `@tailwindcss/postcss`.
  - **Authentication:** `@clerk/nextjs` (`v7.3.1`) with `AuthGate` component.
  - **PDF Viewing Engine:** `react-pdf` (`v10.4.1`) with custom HTML/CSS coordinate overlay layer.
  - **Data Visualization & Toasts:** Plotly.js (`v3.5.1`), `react-plotly.js` (`v2.6.0`), and Sonner (`v2.0.7`).

- **Vector Database & Search:**
  - **Vector Database:** Pinecone (`pinecone==5.4.2`), index name `leasesight-index`.
  - **Vector Dimension:** 768-dimensional float vectors generated by `sentence-transformers/all-mpnet-base-v2` (SBERT).
  - **Namespace Isolation:** Multi-namespace architecture querying both `academic_baseline` and tenant-scoped `user_{user_id}` namespaces in parallel via `retrieve_dual_namespace`.
  - **Search Fallback:** In-memory fallback to structured JSON spatial maps (`data/json_maps/{file_name}.json`) if Pinecone is empty or unreachable.

- **Asynchronous Queue / Task Worker:**
  - **Task Manager:** FastAPI `BackgroundTasks` framework (in-memory async worker queue).
  - **Pipeline Steps:** Document upload triggers `run_full_pipeline`, which sequentially executes PDF layout parsing, vector indexing, entity extraction (`UniversalProcessor`), and background live evaluation verification (`_run_background_live_verification`).

- **Deployment Infrastructure:**
  - **Containerization:** Containerized backend service via `Dockerfile` (Python 3.11 slim base).
  - **Reverse Proxy & SSL:** Caddy server (`Caddyfile`) handling HTTPS termination and reverse proxying to FastAPI on port `8080`.
  - **Hosting Setup:** Next.js frontend configured for Vercel (`vercel.json`) and backend script utilities (`DEPLOY.sh`, `RESTART_ALL.sh`, `CADDY_RESET.sh`).

## 2. Ingestion & Structural Chunking Engine Analysis

- **Parser Utilized:**
  - Primary parser: **Azure Document Intelligence** (`DocumentAnalysisClient` using the `prebuilt-layout` model). Extracts text lines alongside physical bounding box polygon coordinates `[{"x": p.x, "y": p.y}]` for every page.
  - Fallback parser: `pypdf` (`PdfReader`) text extraction when Azure credentials or network endpoints are unavailable (`_fallback_spatial_data_from_pdf`).

- **Parent Chunk Configuration:**
  - **Token/Character Size & Overlap settings:** Whole-page layout text ($C_{\text{parent}}$) is constructed per page (`" ".join(line.get("content", "") for line in page["lines"])`). Assigned deterministic Parent ID: `f"{file_name}_p{page_number}"`.
  - **Logical boundary preservation method:** Structural page boundary preservation derived directly from Azure Document Intelligence layout analysis.

- **Child Chunk Configuration:**
  - **Token/Character Size & Overlap settings:** Full-page text is sliced into **250-character Child Chunks** ($C_{\text{child}}$, chunk size = 250 chars).
  - **Linkage mechanism:** Each child chunk is assigned vector ID `f"{file_name}_p{page_number}_c{child_idx}"` and metadata pointers:
    ```json
    {
      "filename": "document.pdf",
      "file_name": "document.pdf",
      "page_number": 1,
      "chunk_index": 0,
      "parent_id": "document.pdf_p1",
      "text": "250-char child chunk text...",
      "parent_text": "Full page text...",
      "coordinates_json": "[{\"text\":\"Line...\",\"bounding_box\":[...]}]"
    }
    ```

- **Vector Embedding Target:**
  - Embeddings are constructed **exclusively on the 250-character Child Chunks** ($C_{\text{child}}$) using the local `sentence-transformers/all-mpnet-base-v2` model (768-dim float vectors, `normalize_embeddings=True`).

## 3. Vector Database Metadata & Linkage Mapping Schema

- **Stored Vector Metadata Payload:**
  Each Pinecone vector point contains the following JSON metadata structure:
  ```json
  {
    "filename": "AgapeAtpCorp_SupplyAgreement.pdf",
    "file_name": "AgapeAtpCorp_SupplyAgreement.pdf",
    "page_number": 1,
    "chunk_index": 0,
    "parent_id": "AgapeAtpCorp_SupplyAgreement.pdf_p1",
    "text": "THIS SUPPLY AGREEMENT is made and entered into...",
    "parent_text": "FULL PAGE 1 TEXT...",
    "coordinates_json": "[{\"text\":\"THIS SUPPLY AGREEMENT\",\"bounding_box\":[{\"x\":0.5,\"y\":1.0},{\"x\":3.5,\"y\":1.0},{\"x\":3.5,\"y\":1.2},{\"x\":0.5,\"y\":1.2}]}]"
  }
  ```
  `_truncate_metadata` ensures metadata remains below Pinecone's 40KB hard limit while safely preserving `parent_id`, `parent_text`, `text`, and `coordinates_json`.

- **Cross-Clause Dependency Mapping:**
  Cross-section and spatial linkages are dynamically resolved during retrieval and rendering. `find_coordinates` in `scripts/visual_anchor.py` matches the quote's 25-character alphanumeric fingerprint against `data/json_maps/{file_name}.json` to extract precise bounding boxes for UI highlight rendering.

## 4. Retrieval Mechanism & Scoring Formula

- **Retrieval Type:**
  - **Hybrid Retrieval:** Blended Dense Vector Search (`sentence-transformers/all-mpnet-base-v2`) + Sparse Keyword Search (`BM25Okapi` via `rank_bm25`).
  - **Multi-Namespace Aggregation:** Dual querying across `academic_baseline` and tenant namespace (`user_{user_id}`).

- **Scoring Equation & Blended Fusion Method:**
  Candidate matches retrieved from Pinecone are re-ranked using the exact blended hybrid scoring equation:
  $$S_{\text{hybrid}} = 0.7 \cdot S_{\text{dense}} + 0.3 \cdot S_{\text{BM25}}$$
  where $S_{\text{dense}}$ is the Pinecone cosine similarity score and $S_{\text{BM25}}$ is the normalized `BM25Okapi` score across candidate chunks. Matches are sorted by $S_{\text{hybrid}}$ in descending order:
  ```python
  bm25 = BM25Okapi(corpus)
  raw_bm25_scores = bm25.get_scores(q_tokens)
  max_bm25 = max(raw_bm25_scores) if max(raw_bm25_scores) > 0 else 1.0

  for idx, m in enumerate(deduped_matches):
      s_dense = float(m.get("score", 0.0))
      s_bm25_norm = float(raw_bm25_scores[idx]) / max_bm25
      s_hybrid = (0.7 * s_dense) + (0.3 * s_bm25_norm)
      m["score"] = round(s_hybrid, 6)
  ```

- **Parent Context Expansion:**
  When a 250-character Child Chunk matches, the retrieval engine resolves and expands the chunk back to its full `parent_text` ($C_{\text{parent}}$) before passing the context payload to the Groq LLM:
  ```python
  for m in deduped_matches:
      meta = m.get("metadata")
      if meta and meta.get("parent_text"):
          meta["context_text"] = meta["parent_text"]
  ```

## 5. Deterministic Extraction Gate & Schema Validation

- **Pydantic / Validation Schemas:**
  Primary audit response structure defined in `api/schemas.py`:
  ```python
  class Finding(BaseModel):
      label: str
      value: str
      evidence_quote: str
      verified_grounded: Optional[bool] = True

  class Obligation(BaseModel):
      label: str
      date: str
      description: str
      evidence_quote: Optional[str] = "Not Found"
      verified_grounded: Optional[bool] = True

  class AuditResult(BaseModel):
      findings: List[Finding]
      obligations: Optional[List[Obligation]] = []
      summary_paragraph: str
      risk_score: int
      warnings: List[str]
      annotations: List[Annotation] = []
  ```

- **LLM Prompting Constraints & Verbatim Quote Verification:**
  Single-pass `AUDIT_PROMPT` in `scripts/full_audit.py` enforces verbatim quote extraction. After LLM extraction, `_normalize_report` verifies every `evidence_quote` against the document text:
  ```python
  clean_context = re.sub(r'[^a-zA-Z0-9]', '', context_text or "").lower()
  clean_q = re.sub(r'[^a-zA-Z0-9]', '', quote).lower()
  item["verified_grounded"] = clean_q[:25] in clean_context
  ```
  The final dictionary is strictly validated using `AuditResult.model_validate(out)`.

- **Fallback Behavior:**
  If the LLM endpoint is rate-limited (HTTP 429) or unavailable, the system invokes `_fallback_audit` in `scripts/full_audit.py`, running deterministic regex pattern matching over raw document text to extract core fields with `risk_score = 5`.

## 6. Frontend & Visual Analytics Implementation

- **Real-Time Progress:**
  - **Polling Architecture:** The Next.js frontend (`api.ts`) polls backend endpoints `/api/index-status/{filename}` and `/api/live-evaluation/{filename}` during document upload and processing.
  - **State Updates:** Processing states (`QUEUED` -> `PROCESSING` -> `COMPLETED` / `FAILED`) are rendered live in `FileUploadStatus.tsx` and `MigrationDashboard.tsx`.

- **PDF Preview & Highlight Linkage:**
  - **PDF Rendering:** `RightPane.tsx` uses `react-pdf` (`Document`, `Page`) to render PDF documents.
  - **Coordinate Transformation:** Bounding box highlights are computed by `find_coordinates` in `scripts/visual_anchor.py` and mapped to CSS overlays:
    $$\text{pxX} = \frac{\text{ann.x}}{8.5} \times \text{pageWidth}, \quad \text{pxY} = \frac{\text{ann.y}}{11.0} \times \text{pageHeight}$$
  - **Interactive Jump:** Clicking the locate button ("🔍") in finding cards or chat messages calls `scrollIntoView({ behavior: 'smooth' })` to focus the target page and display pulsing highlight boxes.
